# 决定记录

## 2026-09-17：对比的官方臂用哪个版本

**背景。** 第一轮 47×2 对比跑的是 SDK `0.1.0rc7`（2026-08-17）。这是适配器"最接近冻结点的可安装版本"规则的结果 —— rc.8 从未发布到 PyPI。而上游当时已经到 `dsh-v0.1.6-alpha.1`（2026-09-15），中间隔 16 个 tag，其中包含会话格式升级到 V3、`ApiProxy` 移除、`ctx.agent` 移除、默认协议改 Messages 等破坏性变更。完整情况见 [version-drift.md](version-drift.md)。

**决定。** 当前这轮保持 rc.7 不变；**此后的对比用最新版本**（`--ak sdk_version=latest`）。

**理由。**

1. 当前这轮已经跑了 3 小时，rc.7 与冻结点 rc.8 在契约层面大概等价（2026-08-21 的增量审计：固定 RPC 名称集合无变化），所以作为**复刻保真度**的检验是成立的。中途换版本会让已经跑完的 47 题作废，而且新版本会引入新的未知数（配置形状、工具面都动过）。
2. 但"对今天的官方谁强"是更常被问的问题，而 rc.7 答不了。此后默认取最新。

**代价，明确记下。** 用 `latest` 意味着每轮对比的基线会漂移，两轮之间的数字不可直接比较。所以每轮必须记录当时解析到的具体版本 —— 适配器现在会把它写进每一条结果行，报告的表头也会印出来。读到没有版本号的通过率时，应当认为它是无效的。

**配套。** `scripts/warm-sdk-cache.sh <version|latest>` 预热 uv 缓存；容器内是离线安装，未预热的版本会明确失败而不是悄悄退回旧版本。
